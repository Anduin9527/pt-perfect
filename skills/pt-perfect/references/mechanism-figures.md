# 机理图（核心原理与动机图）

机理图回答“这个方法为什么成立”。框架图讲数据怎样流动，模块图讲网络里有什么，机理图只讲一件事：论文的核心论断。读者看完应当能用一句话复述该论断，并知道它与已有做法差在哪里。典型例子：卷积的局部窗口与自注意力的全局连接的对照、状态空间模型的扫描顺序、扩散过程的轨迹。

范例源码在 `assets/examples/context-mechanism.tsx`：同一对特征图画三次，分别表示卷积、自注意力和状态空间扫描怎样为一个输出位置汇集上下文。

## 第一步：把论断写成一句话

动笔前写出一句“把 A 换成 B，于是 C”的句子，其中 C 是可以度量的量。写不出来，说明还没有找到核心，继续读引言末段、方法首段和贡献列表，而不是开始画。

| 检查 | 说明 |
| --- | --- |
| 论断只有一个 | 一张机理图只承载一个论断。第二个论断另画一张或放回正文 |
| 有对照对象 | 论断是相对已有做法成立的，图中必须出现已有做法 |
| C 有数字 | 从论文的数值或公式中找到支撑 C 的量，图中按比例画出 |
| 不与已有图重复 | 已有的统计图给出了证据，机理图给出解释，两者配色保持一致 |

例：把“局部窗口内的固定加权”换成“全部位置的内容相关加权”，于是单层内一个输出位置能看到的输入从 $k^2$ 个变为全部 $N$ 个。

## 第二步：选择视觉隐喻

隐喻取决于论断的类型。先在下表中定位，再决定画法。

| 论断类型 | 画法 | 例 |
| --- | --- | --- |
| 谁与谁发生作用（感受野、连接范围） | 特征网格加高亮的作用区域；多层时用堆叠的平面 | 卷积窗口、注意力连线、窗口注意力 |
| 按什么顺序处理 | 网格上的有向折线，按顺序着色 | Mamba 的多方向扫描、光栅顺序 |
| 分布或轨迹怎样移动 | 空间中的点、路径束、流形曲面 | 扩散与桥、流匹配、回归的均值坍缩 |
| 频率或尺度上的分工 | 频谱环带、金字塔层 | 频域分支、多尺度融合 |
| 信息在哪里丢失或保留 | 同一信号经两条通路后的对照 | 下采样混叠、残差连接 |

隐喻须满足：图中每个几何元素都能对应到论文的一个量；找不到对应量的装饰性元素删除。

## 第三步：同一场景，只改一处

对照是机理图的基本结构。各面板使用同一场景、同一视角、同一比例，面板之间只有论断涉及的那一处不同。读者不需要重新理解坐标系，差异自然成为视觉焦点。

- 面板顺序：已有做法在前，本文方法在最后。
- 每个面板的标题写成结论（“自注意力：全部位置”），不写成名词。
- 后面的面板可以用淡色虚线保留前一面板的关键元素，供直接比较。
- 颜色沿用论文中已有图的指派：统计图里代表本文方法的颜色，在机理图里仍代表本文方法。

## 第四步：区分按比例的量与示意的量

机理图必然含有示意成分。每个元素归入下面三类之一，并在 README 的来源表中写明；图注中说明哪些量按比例绘制。

| 类别 | 要求 | 例 |
| --- | --- | --- |
| 按比例 | 由论文数值计算，源码中写出算式 | 两段路径的长度比等于实测的幅度比；窗口大小 $k$ 与正文设置一致 |
| 真实数据 | 从训练或评测产物读取，记录来源与哈希 | 注意力权重取自训练好的模型；轨迹使用训练所用的噪声调度 |
| 示意 | 形状仅用于表达概念，不得标注数值 | 流形的形状、随机生成的权重、轨迹的绝对粗细 |

随机元素使用固定种子（`seeded`），保证重建结果不变。透视或斜投影会改变页面上的长度比，按比例的量以三维空间中的值为准，并在 README 中给出页面上的实际比值。

## 技术路线

| 路线 | 适用 | 做法 |
| --- | --- | --- |
| 二维原语 | 网格、连线、扫描顺序、频谱 | 工具包的 `node`、`wire`、`raw`，与框架图相同 |
| 矢量三维（默认） | 曲面、空间轨迹、堆叠的特征平面 | `Space`：正交投影，曲面拆为着色四边形并按深度排序，输出仍是 SVG 路径 |
| WebGL 光栅 | 需要真实光照、半透明体、数千个以上图元 | 用 three.js 在无头 Chrome 中按 600 dpi 渲染成 PNG，作为 `tile` 嵌入，文字和标注仍由工具包绘制；在来源表中记录渲染脚本 |

默认选矢量三维：输出可在 Illustrator 中编辑，字体与正文一致，文件小，审计和文字宽度检查照常生效。只有矢量路线表达不了所需的材质时才用 WebGL，并且只把场景本身光栅化。

## Space 的用法

```tsx
const sp = new Space({ box, azimuth: -62, elevation: 24, scale: 35 });   // z 轴向上，scale 为每世界单位的 pt
sp.surface((u, v) => [v, u, 0.6 * v * v], { u: [-1.1, 1.1], v: [-1.1, 1.1], n: [10, 24], dark, light, grid: { u: 2, v: 3, color }, edge: { color } });
sp.curve(points, { color, width: 0.4, opacity: 0.6 });                  // 逐段按深度排序，会被曲面遮挡
sp.curve([p, q], { color, width: 0.9, arrow: 4.2 });
sp.dot(p, { r: 2, fill, stroke: '#FFFFFF' });
s.raw('a.space', sp.render(), inner, { kind: 'region' });               // 登记为区域，标签可以放在其上
s.label('a.y', '$y$', { x: sp.at(p)[0] - 1, y: sp.at(p)[1] - 7.5 });    // 用 sp.at 取屏幕坐标来放标签
```

- 所有面板共用同一组相机参数；用一组固定的范围点计算场景的页面包围盒，再把它居中到各面板。
- 曲面的朝向决定可读性：凹面朝向相机，关键点落在可见的一侧。先用低分段数试视角，再提高分段数。
- `bias` 把线和点略微提到曲面之上，避免与所在曲面发生深度冲突；位于曲面上的点使用较大的 `bias`。
- 标签不进入三维场景：文字始终水平，由 `s.label` 绘制并参与审计。`Space` 内部的图元不参与审计，标签与曲面边缘、路径的关系需要看图确认。

## 标注

- 关键对象用数学符号命名，每个面板中位置相同。
- 论断中的数字直接写在对应的几何元素旁（“$k^2$ 个邻居”“全部 $N$ 个位置”）。
- 只在首次出现的面板解释场景元素；图例或一行说明放在面板底行。
- 示意成分不写数值，不写坐标轴刻度。

## 自查

1. 遮住标题和图注，只看图能否说出论断？
2. 各面板之间是否只有一处不同？视角、比例、点的位置是否一致？
3. 图中每个数字是否都能在论文中找到，且与正文一致？
4. 按比例的量、真实数据、示意成分是否已分别写入 README？
5. 图中是否暗示了论文没有主张的内容（例如由示意的粗细读出信噪比）？有则在图注中说明或删去。
6. 按印刷尺寸看，路径束是否仍可分辨，标签是否压在曲面边缘或路径上？
